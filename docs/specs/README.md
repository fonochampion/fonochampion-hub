# Product Specifications

This directory is the source of truth for AI agents and development. These documents start as templates: replace `To be defined` only after confirmation. Separate confirmed requirements, assumptions, and open questions.

## Documents

| Document | Contents |
|---|---|
| Document | Contents |
|---|---|
| [00 — Product brief](./00-product-brief.md) | Problem, users, goals, scope, and success |
| [01 — Requirements](./01-requirements.md) | Functional requirements, acceptance criteria, and non-functional requirements |
| [02 — Architecture](./02-architecture.md) | Tech stack, components, integrations, and architectural decisions |
| [03 — UX and accessibility](./03-ux-and-accessibility.md) | User journeys, interface, responsiveness, and accessibility |
| [04 — Data and integrations](./04-data-and-integrations.md) | Data, privacy, retention, and external services |
| [05 — Use cases](./05-use-cases.md) | Confirmed initial-stage use cases and open behavior |
| [Decisions](./decisions/README.md) | Record of significant decisions |

## Suggested order

1. Define the product brief and record open questions.
2. Derive requirements and acceptance criteria from confirmed goals.
3. Specify user journeys and UX requirements; decide architecture and data needs as requirements become clear.
4. Review dependencies and consistency before implementation.

You do not need to complete every document at once. Do not choose technologies or behavior just to eliminate open fields.
